# 2026-08-23: the descriptor switcher is live without reservations

The revision-1 title-only slice now runs in a normal Hagia session when its
shell profile is enabled. That profile may bind `Super+P` to a reserved
session-owned action that policy cannot claim. The session launches
`hagia-shell --serve` in its own metadata-shell Bubblewrap domain and gives it
only the protected shell socket. Each shortcut sends at most sixteen current
broker descriptors. Stable private slots never disclose Sophia surface
identity.

The shell owns order, selection, visibility, and its candidate generation.
Engine validates the returned slots, renders the existing descriptor overlay,
and waits for the output-local frame to publish its exact targets before it
tells the shell that the candidate was presented. A captured click returns the
presented capability to Hagia Shell for acknowledgement. The broker then checks
its current token, connection, revocation, and descriptor generation before the
session submits an ordinary focus request to Hagia policy. Neither shell
process can focus an application directly.

Loss is fail closed. The session cancels descriptor capture and clears live
targets while retaining old pixels as occlusion. It supervises a replacement
process, negotiates a strictly newer recipient epoch, and does not replay the
old candidate or activation. Malformed replies and failed acknowledgements use
the same recovery path. A transport regression pins the fresh epoch, while the
backend regressions pin inert retained pixels and last-presented target
publication.

Hagia releases now require two independently hashed executables, `hagia` and
`hagia-shell`; installed startup and every Hagia physical builder pass the
shell path explicitly. The Rust all-feature suites, installed-package gate,
and Rust/C/Nim shell behavior corpus pass. Hagia's verifier passed its format,
Nim, cross-repository, and shell checks, then stopped at the host dependency:
the repository requires Z3 4.16.0 and the host provides 5.1.0.

This does not promote the row or enable the compiled profile. Core
`GrabPointer` and admitted XI grabs still live only in the X frontend, so
Engine cannot make a shell capture yield to that explicit owner. Those grabs
must join the existing application lease handshake first. The following signed
installed run will open the list, activate one presented row, crash and
reconnect the shell, then repeat activation and withdrawal with clean teardown.
Work-area reservations, previews, icons, MRU policy, and generic texture
transfer remain outside that gate.

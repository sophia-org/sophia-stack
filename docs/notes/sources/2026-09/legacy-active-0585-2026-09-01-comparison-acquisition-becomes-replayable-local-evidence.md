# 2026-09-01: comparison acquisition becomes replayable local evidence

Historical source, not a current status claim. <a href="../../../history/research-log-2026-09-06.txt">Original snapshot</a>,
lines 18470–18525. The heading supplies the recorded date.

The 39-row diagnostic contract previously began after acquisition: its public
`run RUN SAMPLE_LOG` accepted a completion line no repository tool could
produce. That seam has been removed. The public row flow is now
`status -> attest -> preflight -> capture`; the prepared schedule, rather than
the caller, supplies stack, version, workload, repetition, duration, topology,
and executable version identities.

The runtime attestation is a mode-0600 local record bound to an owned live
supervisor PID and start tick. It rejects a supervisor executable from another
stack and requires XLibre's dedicated prefix to name the exact pinned commit.
This is intentionally not a display-manager controller: the operator selects
the named greetd stack, and no comparison code uses SSH or changes greetd.

One Rust owner now launches the workload, holds its process roots, samples the
union of workload and compositor trees each second, and tears down only children
it created. CPU and fault figures are deltas from the measured-window baseline;
memory, process, thread, and descriptor populations are absolute. A vanished or
unreadable root fails the row instead of silently shrinking its totals.
Short workloads all measure 60 seconds, resize produces exactly 120 request
latencies, and soak measures two hours.

Kernel `drm_vblank_event_delivered` time is the authoritative frame population.
The only privileged code is a fixed-name shell adapter that validates the
user-owned attempt directory, owns a private tracefs instance, and disables and
removes it on exit. Native compositor timing remains an availability diagnostic,
never a fallback for absent kernel evidence.

An attempt is not a sample log. It is five raw records, a deterministic replay
result, and an internal exact-file checksum ledger. The run ledger separately
binds that result to the next schedule path. Partial incoming attempts and
unsealed archive entries block later status/verification; extra files,
truncation, reordered identities, mixed CRTC time, and post-bind mutation fail
closed. Reports now retain resource, allocation, failure, launch/settle/resize,
and p50/p95/p99/max kernel frame fields with `verdict=none`.

The repository now supplies isolated Hagia, niri, and xmonad profiles, a fresh
Firefox profile plus loopback readiness fixture, and a changing pseudo-random
Kitty stream. The native five-second sampler capacity increased from one hour
to two hours ten minutes, so a two-hour CP-14.3 run can remain nonsaturated.

A final provenance audit corrected the initial xmonad `0.18.1.9` label before
any physical row was admitted. That number belongs to the host launcher
executable package. The standalone repository profile actually links xmonad
core `0.18.1` and xmonad-contrib `0.18.2`; installation now queries GHC's
active package IDs, compiles against those exact IDs, verifies the compiled
binary's own version, and retains both runtime versions in its sidecars. GHC
objects are confined to a prefix-local temporary directory and removed, so
reference installation cannot dirty the Sophia candidate.

No physical matrix row or fresh current soak was captured in this implementation
session. The immediate external prerequisite is an exact XLibre build from
`56be9f4320ef121dc5d4bc40a6365d995512d3bc`; `/usr/bin/Xorg` 21.1.24 is not
that stack.
